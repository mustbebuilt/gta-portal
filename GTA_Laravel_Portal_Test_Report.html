Remaining limits

  • Actual Martin repository/source/target private aliases and managed Cloud database/bucket were not accessed. Local results do not establish hosted installation, TLS/bucket policy, redeployment, restore or browser acceptance.
  • Copy planning covers known upload references and retained metadata in eight source families. It does not discover unregistered bucket/directory objects or reconcile other applications. Logical disk/path deduplication does not merge physical aliases.
  • Preview and record use database/configuration metadata without uploaded-file/network reads. Execution is off by default, staging-only and explicitly requires unchanged bindings, exact plan version/hash and the configured opt-in.
  • Console-origin technical audit and an operator-supplied reference are not an authenticated human signature, independent business approval, assessment decision or migration/cutover authorisation.
  • Verified staging copies means finite sequential SHA-256/size readbacks and final source/reference/configuration checks succeeded at read time. No atomic freeze, complete backup or ongoing consistency guarantee. Use a controlled write window and independently verify actual sources/targets.
  • Exclusive destinations are not overwritten or adopted. Failed/partial outputs remain. An interrupted/final-audit-failed run can stay Running; it cannot automatically retry/resume. Database rollback cannot undo object writes. Reconcile using the protected manifest/events privately.
  • Original files, application references, disk pins/defaults, saved schemas and snapshots remain unchanged. Portal downloads continue using the original locations. No cutover/relink/delete/rollback-switch workflow or production execution is supplied.
  • The default copy cap is 20 MiB per declared object. A private temporary spool may spill past 2 MiB. Larger/unknown legacy uploads need a separately reviewed workflow; staging root/temp/bucket permissions need actual acceptance.
  • Native database proof uses local MariaDB 11.8.6/PDO MySQL, not Oracle MySQL or the exact managed Cloud engine. The signed S3 conditional-copy fixture uses the actual locked SDK but is not actual Cloud/R2 acceptance.
  • One additive plans/events migration; no dependency changes. All 531 source PDFs, Composer/lock/vendor bytes retained. No real learner data, credentials, external messages, real copies or deployment used.
